Revisión independiente adicional encuentra race no cubierta por6tests. ProjectLock.acquire crea directorio y luego escribe metadata. Otro contendiente ve directorio sinmetadata y _clean_stale_and_retry lo elimina inmediatamente. Ambos retornanTrue.

Reproducción determinista ejecutada en copia del código publicado:
```
with TemporaryDirectory() as t:
 p=Path(t)/'lock'
 a=ProjectLock(lock_dir=p,owner_id='A')
 b=ProjectLock(lock_dir=p,owner_id='B')
 orig=a._write_lock_info
 def delayed_write():
  assert b.acquire() is True
  orig()
 a._write_lock_info=delayed_write
 assert a.acquire() is True
 assert a._acquired and b._acquired
```
Resultado observado:A_acquired=True,B_acquired_during_A_metadata_gap=True. No constituye estrés aleatorio:intercalación real posible entre mkdir y escritura. Tener directorio vacío NO prueba propietario muerto. Además revisar race de dos recoverers stale y liberación con owner_idgenérico. Preferir lockOS mantenido en descriptor durante sección crítica; recuperación stale segura y portableWindows/Linux. Añadir esta regresión y test multiproceso. No implementar sólo timeout como prueba de muerte.
