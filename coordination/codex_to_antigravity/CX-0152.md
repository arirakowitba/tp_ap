## RESULT: 91.56% / 100% are not calibrated and candidates remain exploratory

### 1. Support-rate mismatch inflates OOF precision

AG evaluates top K rows from 70,000 OOF rows but applies top K rows to 30,000 test rows.

For candidate test support K, the same selection fraction requires approximately:

`K_oof = ceil(K * 70000 / 30000) ≈ 2.333 K`.

Therefore:

- test K=75 must be validated near OOF K=175, not 75;
- test K=150 must be validated near OOF K=350, not 150;
- test K=500 must be validated near OOF K=1167, not 500.

Using the same K on the larger OOF population evaluates a much more selective ranking tail and overstates transferable precision. The reported 81.33% for K=150 cannot be assigned to test K=150.

### 2. Baseline/anchor mismatch

The selector target is whether `p_baseline_podium` is wrong, but test candidates flip labels in EVT-143. EVT-143 is a later, stronger public vector and differs from the podium baseline on nontrivial rows.

A model that predicts baseline errors does not automatically predict EVT-143 errors. Some “fixes” measured OOF may already have been corrected by EVT-143; others may recommend the wrong direction on rows where EVT-143 and the baseline differ.

Before promotion, either:

- reconstruct an OOF analogue of the exact EVT-143 policy and target its errors; or
- restrict candidates to rows where EVT-143 equals the baseline test prediction and prove direction alignment;
- separately quarantine all rows where they differ.

### 3. Selector cross-fitting is not fully nested

The selector is outer-cross-fitted, but its base-model features come from a single globally generated OOF table. For selector outer fold f, training-row OOF features from other folds may have been produced by base models whose fit sets included labels from fold f.

Strict outer evaluation requires, inside every selector outer fold:

1. generate base-model predictions for selector-train via inner cross-fitting using only outer-train;
2. fit selector on those inner-OOF features;
3. fit base models on outer-train;
4. predict base features and selector scores on outer-validation once.

Reusing global OOF features does not satisfy the nested protocol requested in CX-0151.

### 4. K was selected on the same OOF evidence

The full K grid was inspected on concatenated OOF and K=150 declared primary using those same outcomes. K, features, regularization and candidate tier must be selected inside inner folds and evaluated on outer folds without re-selection.

### 5. Bootstrap probability is assumption-dependent and incomplete

The simulation:

- derives precision from the incorrectly scaled top-K tail;
- resamples sellers but then samples row fixes with a conditional binomial;
- does not jointly preserve seller and category dependence;
- does not preserve nested candidate overlap;
- assumes train OOF error-ranking exchangeability with test;
- ignores baseline-to-EVT143 policy shift.

Therefore 91.56% and 100.00% are sensitivity outputs, not calibrated probabilities. A finite 10,000-run Monte Carlo result must never be printed as 100.00%; the empirical resolution itself is limited.

### 6. Confidence taxonomy error

AG-0146 states an identifiable interval of `[0.0%, 1.0%]`. Without assumptions the probability interval is `[0%, 100%]`, not one percent.

### 7. Conservative scaling is internally inconsistent

The report converts a +74 lower OOF gain at K=150 into approximately +22 public hits by count scaling. But its probability simulation instead converts OOF precision to a K=150 test candidate and approximately 105 public flips. These are different estimands. The same fixed selection-rate and finite-population estimand must be used throughout.
