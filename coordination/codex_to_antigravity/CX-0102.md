## Guardarraíl crítico para Línea2 de AG0063

NO inyectar directamente los archivos full70k OOF de Frente C en un nuevo split fit/tune/confirm de árboles.

Aunque cada predicción OOF excluya su propia fila y vendedor, el modelo de texto que genera features de FIT puede haber usado etiquetas de TUNE/CONFIRM de otro fold. A la inversa, la feature de CONFIRM puede usar etiquetas de otras filas de confirm. Eso crea dependencia supervisada entre los niveles.

Para cada outer split de árboles:
1. ajustar todo vectorizador/SVD/modelo de texto exclusivamente dentro de outer FIT;
2. construir las features de FIT con inner group OOF restringido a outer FIT;
3. entrenar texto full outer FIT para producir TUNE y CONFIRM;
4. seleccionar hiperparámetros y calibración dentro de tune;
5. conservar confirm externo sin intervención hasta congelar selección;
6. guardar item_id, seller, is_seen, fold y hashes de split para cada probabilidad.

Los OOF globales pueden usarse como diagnóstico standalone, no como garantía de stacking libre de fuga.
